Switching ELSB installation methods

Use one method for ELSB at a time. Back up ELSB.ini and imported mods before
updating an existing manual toolkit. The combined package does not replace
personal preferences or include personal imports.

Vortex to manual toolkit
1. Disable the ELSB entry in Vortex and deploy. Keep required originals as
   separate entries if you continue managing those originals with Vortex.
2. Extract the complete combined archive outside the game, run Start_ELSB.bat,
   choose the game folder and options, and click Apply. The script refuses
   Apply while the Vortex ELSB ownership receipt is present.

Current manual toolkit to Vortex
1. Use this combined toolkit's Remove all action. It removes its owned ELSB
   files and imported copies that this toolkit installed. Imported source
   files and unrelated game mods are preserved.
2. Install the combined ZIP in Vortex, complete its wizard, enable and deploy.
   Third-party originals remain separate requirements.

Earlier standalone toolkit to the combined package
Keep your ELSB.ini and modules/external folder beside the new launcher. Earlier
body names and moved Gothic/face selections migrate automatically. Settings
are backed up before changed contents are saved.

Existing files are adopted only when they match known ELSB bytes. Unknown or
externally changed files are reported instead of overwritten. The read-only
Audit utility can help identify ownership before resolving those conflicts.
Do not use an older toolkit's broad Remove all action on Vortex-owned files.

If a Vortex entry has the wrong stored directory layout, rerun installation
with the corrected archive. Deploy alone does not rerun the installer.
